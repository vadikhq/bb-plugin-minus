# Устранить краткую подмену цитат

Владелец заметил: иногда один текст появляется ненадолго, затем заменяется другим. Неизменённая установленная версия воспроизвела эту последовательность при запаздывающем API: новая видимая строка получает временную цитату; ответ сервера относит её к прежней группе, и старая сохранённая цитата группы вытесняет уже показанную. Новый случайный выбор или AI-запрос в момент подмены не выполняется.

Владелец разрешил: «Переход и исправление; без merge и установки: Разрешаю указанный переход ветки и исправление подмены цитат». Переход выполнен в прежней папке: bb/minus-quote-copy → bb/minus-stable-quotes от main `1383e2777f956727122e199cd98e5c98f8217f87`. Старые ветка/upstream/merged PR #6 и все 36 исторических untracked файлов сохранены побайтно. Нового Git checkout/worktree не создавалось. Источник согласия — прямой ответ текущего треда; provider не предоставил ID сообщения.

## Решение и границы

Приоритет получает цитата продолжающегося видимого блока этой панели. Перед пересборкой частей сохраняется снимок его участников и показанного текста. При изменении server/fallback ключа связь узнаётся по пересечению участников. Исторические цитаты строк и общие кеши применяются после этого; уже показанный в соседней панели текст не перезаписывается чужой панелью.

Снимок строится из того же индекса собственных сводок, который существовал до исправления; нового document-wide discovery или сетевого запроса не добавлено. Выборы панели хранятся через WeakMap по контейнеру, показанный текст маркера — через WeakMap по собственному элементу. Detached DOM не удерживается этими ключами; dispose очищает группировку. Настоящая смена словаря создаёт прежний новый lifecycle и не получает старую цитату.

Счётчик, статус и точные native/Thought/delegation boundaries продолжают обновляться. При доказанном объединении двух видимых частей сохраняется цитата ведущей части; новая общая сводка имеет актуальный счётчик и перенесённый фокус. Произвольный timeout/TTL, задержка показа, новые настройки, фильтр по возрасту истории или другая архитектура не вводились.

Backend, данные, словари и их выбор, лайки, clipboard API и SDK pin 0.6.79 не меняются. Лайк и копирование используют именно показанный текст. Путь настроек остаётся через принятое меню «…» → Minus settings → список понравившихся; новой rail-поверхности нет.

## Регрессии и проверка

- [x] Задержанный API не заменяет уже показанный текст; счётчик обновляется.
- [x] Ошибка и повтор чтения не подменяют цитату.
- [x] Две панели одного треда сохраняют свои показанные тексты при чередующихся обновлениях.
- [x] Возврат ранней строки перед остающейся видимой группой сохраняет текст, включая отсутствие API после ошибки.
- [x] Настоящие boundaries разделяют группы; доказанное объединение сохраняет ведущую цитату, счётчик и фокус.
- [x] Смена словаря очищает прежний lifecycle; лайк и clipboard получают видимую цитату.
- [x] Конечный поток завершается; собственные frames/timers и DOM presentation очищаются.

На исходной версии четыре из первых пяти новых проверок падали на самом видимом тексте. Два дополнительных edge cases, найденных независимым ревью, воспроизведены отдельными отрицательными тестами до исправления; ранние FAIL сохранены, за итоговый PASS не выдаются. [Итоговые проверки](verification/2026-11-06-stable-quotes/verification.json) и [JUnit](verification/2026-11-06-stable-quotes/tests.junit.xml) относятся к текущим байтам. Повтор полной проверки потребовался после реального изменения runtime, а не из-за нового чата или пересказа.

Конечный браузерный сценарий сравнивает baseline/candidate actual source modules с одинаковыми задержанными ответами и возвратом ранней строки. Это отдельный in-memory DOM fixture в isolated headless Chromium, без live запросов. Он проверяет текст и геометрию, но не изображает проверку native React virtualization или физического телефона.

Отдельно проверяется действующий принятый native BB UI с candidate bundle только в собственном disposable client: светлая/тёмная темы, desktop/narrow, touch и увеличенный текст, копирование/ошибка/повтор/pending guard/клавиатура/фокус/настройки/раскрытие. Все Minus RPC изолированы official SDK fake host с собственной SQLite, HTTP mutations и исходящие realtime frames заблокированы. Рабочий источник/настройки/данные не записываются; свои contexts закрываются. Весь длинный текст при 320 px и 200% шрифте требует прокрутки — один PNG не доказывает его полную читаемость.

Итог этой редакции: 160 тестов, TypeScript и официальная сборка PASS. В конечном Chromium fixture исходная версия меняла текст, а кандидат сохранял его; при 390 px высота исходной сводки менялась с 107 до 87 px, у кандидата оставалась 107 px. В обоих случаях выполнены два выбора цитаты; новый выбор в момент ответа не нужен. После cleanup нет собственных скрытых строк или сводок.

Три конечных native UI прогона завершены: 1280 px, светлая тема/английский; 390 px, тёмная тема/русский/touch; 320 px, светлая тема/английский/touch/200% шрифт. Основные действия и геометрия PASS, page errors нет. Реальный clipboard содержит показанный текст и автора. Рабочие source/bundle/status/error count до и после совпали; contexts/browser закрыты. Полная совместимость соседних расширений и unrestricted realtime этим методом не подтверждены.

Первая попытка native UI завершилась timeout на загрузочном skeleton до появления цитат; она сохранена как FAIL. Инструментированный повтор неизменённых байтов прошёл, причина первого отказа не доказана. Между попытками запись диагностического лога получила ENOSPC ещё до запуска браузера. Удалена только созданная этой задачей и уже ненужная копия зависимостей checkout; зависимости подготовленного артефакта сохранены. Массовой очистки и изменений рабочего BB не было.

## Дизайн и нагрузка

Единая принятая основа — [меню справа сверху](2026-11-04-quote-actions.md), prototype `ef974fc5`, поверх [сохраняемых лайков](2026-11-02-quote-likes.md). CSS, иконки, шрифты, цвета и плотность не менялись. `impeccable` Operate/harden: проверяется стабильность уже показанных данных при задержке/ошибке/повторе; `frontend-design`: сохраняются incumbent BB tokens и принятая иерархия сердца/текста/меню. `bb-plugin-workflow`: принятое восстановление не вводит новый макет; `bb-plugin-authoring`: официальный API, прежний SDK и lifecycle, без правок runtime BB. Независимое ревью и актуальные UI evidence фиксируются для этой редакции.

В детерминированном DOM сценарии количество запросов, обходов своей и соседней ленты сравнивается отдельно. Устранение ненужной замены текста сокращает работу представления; отсутствие бесконечного цикла в fixture не является профилем CPU/RAM машины. Этот PR не объявляет единственную причину исторических зависаний или устранение всех возможных скачков native виртуализации.

## Стадия и обратный путь

Кандидат подготовлен отдельно от установленного Minus. Merge, install/reload и общий restart не разрешены и не выполняются. До установки обратный путь — оставить принятую рабочую версию. Окончательный title/body будущего PR показывается владельцу перед публикацией. Старые source/review/UI evidence сохраняют своё историческое происхождение и не приписываются новым байтам.
