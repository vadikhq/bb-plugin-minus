# Лайки цитат в чате и настройках

Пользователь может поставить или снять лайк сердечком рядом с цитатой. Сохранённый лайк виден у её повторов и в общем списке понравившихся из всех словарей. Шестерёнка у цитаты открывает существующие настройки Minus и переводит фокус к списку. Активный словарь не фильтрует понравившиеся.

## Решения и текущая основа

Владелец поручил сохраняемые лайки, выбрал «Красное заполненное» и принял компактную вёрстку: «Отступы и переносы Minus: Принимаю обновлённый макет». Текущий единственный макет — `minus-likes-preview.html` в материалах назначенного writer, SHA256 `d918e8f8c3379bf1acb4a49b4908eb3f4ddf86b72ab9cea7a0a9efa6343ba3c4`. Его красное сердце, серый текст, средняя точка, первое выравнивание строки, естественные переносы и слот настроек сохраняются. Новых вариантов интерфейса не создаётся.

Прямое поручение «Устанавливать лайки» разрешает работу над функцией; отдельное согласие «Разрешаю указанный переход к лайкам» относится к `bb/minus-observer-cost → bb/minus-quote-likes` в том же checkout от `main@77de1c1d6c783b4bf5746cb8f5bd655ef0146b5c`. Старые ветки/upstream/PR и все 36 локальных материалов сохранены. Время инструментов полностью отменено позднейшим решением владельца и не возвращается.

Поиск готовых решений уже проведён: Bookmarks BB сохраняет сообщения/выделения, VS Code Motivational and Inspirational Quotes показывает цитаты; принятые словари Minus, общее состояние повторов и его настройки требуют доработки Minus. Поиск не повторялся без новых оснований.

## Данные и состояния

Официальная миграция добавляет таблицу понравившихся и монотонную редакцию списка, не изменяя существующую миграцию словарей. Лайк — снимок текста, автора, раздела, источника, указателя и словаря. Повторное использование ID для нового текста не наследует лайк. Переименование словаря не переносит и не удаляет прежнюю запись. Лайки не имеют внешнего ключа на текущий набор: обновление словаря не уничтожает понравившийся текст.

Запись передаёт явное `liked=true/false` и идемпотентна; повторный клик во время запроса не создаёт второй запрос. Подтверждение выполняется отдельным чтением. При потере ответа повторяется то же желаемое состояние. При ошибке сохраняется последнее подтверждённое состояние, появляется доступный повтор. Поздний ответ с меньшей редакцией не отменяет новую подтверждённую запись. Открытые поверхности получают серверную инвалидацию.

Новый UI имеет английскую основу и русский перевод через официальный Localization `get(null)`, с English fallback при отсутствии API/поддерживаемого языка. Язык не записывается. Данные цитат не переводятся как UI. Settings — существующий `/settings/plugins/minus#minus-favorites`; новый rail-вход не добавляется. SDK остаётся 0.6.79, SDK/core/vendor и общий BB не меняются.

Ревью выявило и сняло пять P2: stale retry после серверного подтверждения; размер touch-сердца в settings; кража фокуса после delayed unlike; fallback после ошибки языкового API с retained data; отсутствующая колонка settings в реальном render. Колонка задаётся явным scoped CSS. Принятая микроанимация учитывается ожиданием её конечного завершения; ignored pending-click повторно её не запускает. Ранние неуспешные проверки не объявлялись пройденными и сохранены локально. Отдельный тест проверил возврат к прежнему dictionary-only списку миграций с последующим re-upgrade и сохранением лайков; это не actual live rollback.

Процесс сверен по `bb-plugin-workflow` и `bb-plugin-authoring`: сохранены scope, официальный storage/RPC/lifecycle, существующие Settings и отсутствие нового rails; SDK pin не менялся. `impeccable` Operate/animate/harden и `frontend-design`: принятую основу сохраняют native токены, первая строка, серый текст и один красный акцент; новые состояния/keyboard/touch проверены по реальному render. Отсутствие PRODUCT.md/DESIGN.md не использовано для нового дизайна: действующий принятый макет и native implementation остаются основой.

## Стадия и обратный путь

Рабочая установка остаётся на принятом performance исправлении PR #4. Кандидат лайков к live runtime не подключён. Проверки, независимое ревью, commit/push/готовый отдельный PR и разрешённая установка различаются по стадии. До активации сохраняются fresh source/jobs/config/dictionaries/data/errors preflight и проверяемый backup/restore. После появления лайков remove особенно требует сохранности базы; старую копию поверх новых записей не восстанавливают. Возврат кода должен сохранять новые таблицы и все актуальные данные.
